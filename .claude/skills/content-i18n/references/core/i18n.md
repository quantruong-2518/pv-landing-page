# i18n rules

## The forbidden pipeline

```
vi → translate en → translate ko          FORBIDDEN
```

## The required pipeline

```
                  semantic spec
                 /      |      \
               vi      en       ko
            native  native   native
             writer  writer   writer
```

Each writer reads the spec, the locale rules, the glossary and the brand rules. None of them reads
another locale's output.

## Preserve

```
meaning            claim strength     mechanism          qualifier
system state       user intent        action             consequence
CTA intent         terminology        placeholders       numbers (value, not format)
```

## Do not preserve

```
word order         sentence structure   idioms
rhetorical form    source grammar       sentence count
punctuation style  capitalization rules
```

Three locales may legitimately produce three different sentence counts for the same spec. Korean
often needs fewer clauses than English; Vietnamese often needs a different information order. That
is correct output, not drift.

## Numbers and formats

| | EN | VI | KO |
|---|---|---|---|
| Decimal | `17.6 TOPS/W` | `17,6 TOPS/W` | `17.6 TOPS/W` |
| Thousands | `15,000` | `15.000` | `15,000` |
| Date | `Sep 2026` | `9/2026` | `2026년 9월` |
| Currency | `KRW 2bn` | `2 tỷ KRW` | `20억 원` |

The **value** is invariant. The **format** is local. Converting 17.6 to "about 18" is a claim
change, not a rounding style.

## Keys

- Keys are stable identifiers. Preserve them across rewrites; a renamed key is a lost translation in
  every other locale.
- Every locale carries the same key set. Missing key → `I18N_MISSING_KEY` (ERROR).
- A key present in one locale but absent from the type definition → `I18N_KEY_MISMATCH` (ERROR).

In this repo only `web/content/vi.ts` satisfies `SiteContent`; the English build was removed on
2026-08-23. With one locale there is no cross-locale parity left for `tsc` to enforce — it checks
that `vi.ts` is shape-complete and nothing more. It cannot see that a string is empty, stale, still
holding its own key path, or mistranslated. The scripts here cover what the compiler cannot, and
`references/core/apply.md` covers what neither can: reconciling the artifact's key set against the
live file in both directions.

## Placeholders

See `scripts/check_placeholders.py`. Rules:

```
never remove      never rename      never translate      never reorder into a broken form
```

`{count}` stays `{count}` in Korean. Translating it to `{개수}` breaks the runtime, and the runtime
failure surfaces to a user, not to you.

Pluralization is not English pluralization:

```
{count, plural, one {# lead} other {# leads}}      en — two forms
{count, plural, other {# lead}}                     vi — one form
{count, plural, other {리드 #개}}                    ko — one form
```

VI and KO have no grammatical plural. Emitting a `one` branch for them is not harmless — it signals
the writer templated English grammar onto the locale.

## Adding a locale

1. Add it to `content-system/brand/voice.yaml` → `locales`.
2. Add `references/locales/<code>.md` with real native rules, not a translated copy of `en.md`.
3. Add the locale to every glossary entry.
4. Add locale UI length limits if the script differs in density.
5. Regenerate from the semantic specs — never from an existing locale.
6. Run `check_i18n.py` to confirm parity.
