# Buyer value

Marketing content must answer: **why should this buyer care?** Not why the feature is clever.

## The translation ladder

```
technical fact  →  operational meaning  →  buyer value  →  (stop)
```

```
Fact:         inference runs on-device
Operational:  requests are processed on the device itself
Buyer value:  less dependency on continuous cloud connectivity
Invented:     cuts infrastructure costs by 40%          ← unsupported, hard failure
```

The fourth rung is where hallucination lives. Climb three, stop.

## Worked ladders

| Fact | Operational meaning | Buyer value |
|---|---|---|
| 17.6 TOPS/W (MINT, mass production since 5/2023) | the accelerator runs inside a field device's power envelope | AI where previously only a sensor could go |
| Analog-PIM, no network dependency | inference completes without a round trip | a decision at the moment of the event, not after the link recovers |
| Korean fabless parent, Vietnamese legal entity | contracts, VAT invoices and warranty in Vietnamese | procurement can actually buy it |
| Six published business sectors | the capability is anomaly detection and predictive maintenance | matches plant maintenance, not a bespoke research project |

## Rules

1. **Different reader, different rung.** The buyer needs the value; the evaluator needs the fact and
   the method. A page for both states the fact *and* the value — it does not average them into
   vagueness.
2. **Do not invent business outcomes.** ROI, payback period, headcount saved, cost reduction — these
   need a customer case, not a plausible arithmetic.
3. **Value is not a feeling.** "Peace of mind" is not a buyer value. "Data does not leave the
   building" is.
4. **Constraints can be value.** "Runs without network access" is a limitation and a selling point
   for the same reader. Say it once, plainly.
5. **The evaluator kills vague copy.** Every buyer-value sentence should have a fact within two lines
   of it that an engineer can check.
