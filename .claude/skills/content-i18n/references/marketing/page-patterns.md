# Page patterns

Reasoning patterns, not templates. Each one is a default order to *think* in; drop a step whenever
the audience's awareness level makes it noise.

## homepage

```
Who are you? → What problem do you solve? → What do you provide? → How does it work?
→ Why should I trust you? → Where is it useful? → What should I do?
```

## landing_page

```
One promise → One problem → One mechanism → One proof → One action
```

A landing page with two CTAs has none. Everything not serving the single action is removed.

## product_page

```
What it is → Who it is for → Capabilities → Mechanism → Specifications
→ Deployment / integration → Limits → Proof → Action
```

Specifications are content, not an appendix. The evaluator arrives here first and reads the numbers
before the prose.

## solution_page

```
Problem → Operational consequence → Solution → Mechanism → Workflow → Value → Proof → CTA
```

The operational consequence step is what separates a solution page from a product page: it makes the
problem expensive before naming the fix.

## use_case_page

```
Situation → Who is involved → What breaks today → What the workflow becomes
→ What is measured → Preconditions → Proof → CTA
```

Preconditions are load-bearing: a use case that only works with a precondition nobody states becomes
a support ticket.

## company_page

```
What we are → Why we exist → Structure and backing → Track record → People → Where we are → Contact
```

Legal identity is trust content: entity name, registration number, address, parent relationship.

## technology_page

```
The constraint in the world → The physical or architectural idea → How it is built
→ What it measures → What it does not solve yet → Where it is used → Depth for evaluators
```

"What it does not solve yet" is not modesty. On a technology page it is the paragraph that makes an
engineer believe the other seven.

## campaign_page

```
Trigger / timing → Specific offer → Who qualifies → What happens when they act → Deadline → Action
```

A campaign without a deadline or a qualifier is a landing page with a banner.

## Applies to all

- One reader question per section (`message-architecture.md`).
- Every claim traced to the ledger.
- Roadmap items labelled at the point of mention, not in a footer.
- The pattern serves the reader's questions. When the two conflict, the pattern loses.
